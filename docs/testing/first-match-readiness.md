## Implemented FT-01 / FT-02 behavior

Match opens with Host / Camera. Host starts pairing; Camera opens the scanner. Pairing starts capture and opens the camera screen with timer, connection indicator, Record/Stop and End as hideable overlays. Stop leaves this screen open; camera settings and the separate camera page are removed from Match. Host Settings displays effective review/buffer durations; advanced local experiment configuration remains in Diagnostics. Camera placement guides have been removed in build 13. Host opens video after Review; Video/Frames switches inside full-screen review with overlay controls; readiness and errors are the only explanatory status text. Completed reviews open the selected full-screen mode, including when the progress screen was closed. Frame review has slider, Previous/Next, count, zoom, Play and Close. Slider input is debounced/coalesced, native decodes do not overlap and closed-screen stale responses are ignored. iPhone capture normalization keeps a stable landscape canvas through rotation; the player fits/crops explicitly.

One-action real recording review reuses calibration for its existing 30-second freshness gate or calibrates automatically, retaining the original native tap through calibration and rejecting a changed connection. No injected Match delay. A prominent Preparing / Receiving / Ready screen shows elapsed wait and opens verified video/frame review automatically. Closing progress keeps the request running; completed reviews also remain accessible from Host. Host waits for a full camera buffer plus a one-second start margin before enabling Review. Native extraction, encrypted transfer, checksum/metadata/decode gates and playback remain from #14. Failed later requests retain a separately labelled previous verified review; at most the current received file plus one previous snapshot remain. Fullscreen native player supports pause/seek and supported slow speeds. Inspection decodes actual frames, with scrollable 1×/2×/3× still zoom. Decoder errors remain explicit; no automatic verdict.

End match requires confirmation, asks the peer to stop/clean, and waits up to eight seconds for acknowledgement. UI claims both-phone cleanup only on success; absent/refused/timed-out acknowledgement instructs local cleanup on the other phone. Playback/inspection or an active extraction may prevent cleanup; close/finish and retry. Saved replay copies live outside temporary match files and survive cleanup. Save/share opens an OS sheet; external destinations are chosen by the player. There is no saved-library browser yet.

## Build 15 transfer investigation

The previous implementation waited for an acknowledgement after each 16 KiB chunk. Both platforms now negotiate bursts of eight ordered chunks (128 KiB raw outstanding). Peers without the capability retain one-chunk acknowledgements; the diagnostic slow path is unchanged. Existing encryption, packet/file bounds, ordering, checksum and decode checks remain in force. Diagnostics reports transfer and verification durations separately.

`tests/TransferBenchmark.swift` exercises actual encrypted engines with 10,000,123 bytes and a simulated 20 ms round trip: legacy negotiation 15.57 s / 612 acknowledgements; eight chunks 2.28 s / 78 acknowledgements (6.82× faster). Both received files match the source exactly. This is a controlled macOS benchmark, not measured camera-to-host throughput. OnePlus instrumentation passed all five TransferTest / ReviewFlowTest checks, including native decode validation and two viewer downloads. Android unit checks, iOS build, TypeScript and controller checks passed. The final Swift ReviewFlowTests run also passed encrypted H.264 transfers, original tap anchoring, two viewers, failure recovery and cleanup on macOS loopback.
